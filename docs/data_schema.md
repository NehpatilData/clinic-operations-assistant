# Data Schema

## 1. Purpose

This document describes the SQL Server schema used by the Clinic
Operations Assistant. The application stores administrative enquiries in
database `ClinicOperationsDB`, table `dbo.clinic_requests`.

The schema details below are based on the SQL Server metadata
screenshots shared for this project and the application's
`src/database.py` code.

## 3. Keys and constraints

The SQL Server screenshots show:

-   `request_id` is the identity column and primary key.
-   The primary-key index is clustered, unique, enabled, and marked as
    the primary key.
-   `status` has a default of `new`.
-   `safety_flag` has a default of `0`.
-   `needs_human_review` has a default of `1`.
-   `created_at` has a default of `getdate()`.
-   `follow_up_status` has a default of `not_required`.

The screenshots do not establish whether check constraints exist for the
allowed status values. The application validates values in Python, but
database-level check constraints should only be documented if separately
verified.

## 4. Workflow values used by the application

### Enquiry status

The `update_enquiry_status()` function accepts:

-   `new`
-   `awaiting_information`
-   `in_progress`
-   `completed`

When status changes to `in_progress` or `completed`, the application
sets `reviewed_at` to the current application-server time.

### Follow-up status

The `update_follow_up_details()` function accepts:

-   `not_required`
-   `pending`
-   `contacted`
-   `completed`

Follow-up notes are trimmed before saving; blank notes are stored as
`NULL`.

## 5. `missing_fields_json` format

The application serializes missing fields using
`json.dumps(missing_fields or [])` and parses them with
`json.loads(...)`.

Example:

``` json
["preferred_date", "preferred_time"]
```

When no fields are missing, the application stores an empty JSON array:

``` json
[]
```

## 6. Application-level data integrity

-   The application validates workflow and follow-up status values
    before updating records.
-   Update functions verify that the requested enquiry exists.
-   Write operations commit on success and roll back on exceptions.
-   SQL values are passed using parameter placeholders rather than
    concatenated into SQL statements.
-   Draft replies are saved for staff review and are not automatically
    sent by the code described here.

## 7. Privacy and safety notes

-   Enquiry messages and phone numbers can contain personal information.
    Use fictional or de-identified examples in demonstrations.
-   Never commit `.env` files, API keys, passwords, or database
    credentials to GitHub.
-   The keyword-based safety screen is not clinically validated and can
    miss or over-flag messages. Follow the clinic's established
    human-review and escalation procedures.
-   AI-generated summaries, classifications, and drafts require staff
    review.
